# 竞速里程 UI 测试重复硬编码配置值

## 现象

竞速赛道长度调整后，配置与配置测试均已更新，但全量测试中的 `RacingPanel.test.tsx` 仍查找旧文案 `4650 m`，导致 80 个测试文件中出现 1 项失败。

## 原因

界面测试重复硬编码了第一关里程，没有从竞速关卡配置读取预期值。配置变化时，测试夹具与实际界面产生了不必要的双重维护。

## 修复

界面测试改为通过 `getRacingStage(1).distance` 生成预期里程；具体数值仍由 `racingConfig.test.ts` 独立校验。

## 防呆

- 数值配置的精确内容由配置层测试负责。
- UI 测试需要验证配置值是否正确展示时，应读取同一公开配置接口，避免再次硬编码数值副本。
- 修改关卡数值后必须运行全量测试，不能只运行配置和引擎测试。

## 验证

重新运行格式检查、类型检查、Lint、全量 Vitest 和生产构建，确认 UI 测试随当前关卡里程通过。
